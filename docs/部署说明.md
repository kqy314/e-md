# e-md 部署说明（Android 手机）

> e-md 是一个基于 Capacitor 的移动端 Markdown 阅读与编辑器。本文档说明如何把当前 Web 工程打包成 Android APK 并安装到手机。

---

## 1. 总体架构

```
Vite + React (src/)
        │  npm run build  →  dist/
        │
Capacitor (npx cap sync android)  将 dist 复制进 android/app/src/main/assets/public/
        │
Android 原生工程 (android/)
        │  gradlew assembleDebug
        ▼
app-debug.apk  →  安装到手机
```

- 前端代码用 **WebView** 渲染（Capacitor 壳）
- 打开/保存真实 Markdown 文件走 **SAF（Storage Access Framework）**，由原生层 [MarkdownBridge.java](../android/app/src/main/java/com/emd/app/MarkdownBridge.java) 实现，通过 `window.MarkdownBridge` JavaScript 接口与前端通信

---

## 2. 前提条件

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 20 | 前端构建 |
| JDK | **24**（关键） | Gradle 8.14.3 与系统默认 JDK 25 不兼容，必须使用 JDK 24 |
| Android SDK | 已安装 Platform 36 + Build-Tools | 由 Android Studio 自带 |
| Android Studio | 任意近期版本 | 用于打开工程 / 连接手机 / 安装调试 |
| 手机 | Android 7.0+（minSdk 24） | 开启「开发者选项 → USB 调试」 |

---

## 3. 首次打包（完整流程）

### 3.1 安装依赖（仅首次或依赖变更时）

在项目根目录 `d:\self_project\e-md` 执行：

```powershell
npm install
```

### 3.2 构建前端并同步到 Android 工程

```powershell
npm run build
npx cap sync android
```

- `npm run build`：先做 TypeScript 类型检查再打包 Vite，产物输出到 `dist/`
- `npx cap sync android`：把 `dist/` 复制到 `android/app/src/main/assets/public/`，并同步原生依赖

> `npm run cap:sync` 可一步完成以上两步（build + sync）。

### 3.3 打包 APK

```powershell
cd android
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\temurin-24"   # 必须指定 JDK 24
.\gradlew.bat assembleDebug
```

构建完成后 APK 位于：

```
android\app\build\outputs\apk\debug\app-debug.apk
```

> **JDK 版本提示**：若 `gradlew.bat` 报错 `Unsupported class file major version` 或 `Java home is invalid`，说明 JAVA_HOME 不是 JDK 24。请确认 `%USERPROFILE%\.jdks\temurin-24` 存在（Android Studio 内置下载的 JDK 24），否则改用你自己的 JDK 24 路径。

---

## 4. 日常更新打包（改完代码后）

```powershell
npm run build
npx cap sync android
cd android
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\temurin-24"
.\gradlew.bat assembleDebug
```

APK 会覆盖到同一位置。手机重装时建议先卸载旧版本再安装（或使用 `adb install -r` 覆盖安装）。

---

## 5. 安装到手机

### 方式 A：adb 命令行（推荐）

手机开启 USB 调试并用数据线连接电脑后：

```powershell
adb install -r android\app\build\outputs\apk\debug\app-debug.apk
```

> 若 `adb` 不在 PATH，使用 Android SDK 自带路径，例如：
> `$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe`

### 方式 B：直接传输安装

1. 把 `app-debug.apk` 通过微信/QQ/网盘/USB 传到手机
2. 手机上点击该文件，允许「安装未知来源应用」后安装

### 方式 C：Android Studio

1. 用 Android Studio 打开 `android/` 目录
2. 连接手机后点击 Run ▶ 直接部署

## 6. 打开文件权限说明（重要）

应用通过 SAF 访问文件，**不需要申请存储权限**：

- 首次「打开」或「另存为」时由系统文件选择器授权，勾选后会获得该文件的**持久读写权限**
- 因此应用能在重启后继续打开「最近文件」并「保存回原文件」
- 若某个文件打不开/无法保存，通常是授权已失效，重新用「打开」选择一次该文件即可恢复

## 7. 常见问题

| 问题 | 原因与解决 |
| --- | --- |
| `gradlew.bat` 报 Java 版本错误 | JAVA_HOME 不是 JDK 24，按 3.3 节指定 `$env:JAVA_HOME = "$env:USERPROFILE\.jdks\temurin-24"` |
| `npx cap sync` 提示找不到 android 工程 | 确认 `android/` 目录存在；若不存在需先 `npx cap add android` |
| 安装时提示「未知来源」 | 在手机设置中允许该来源安装应用 |
| 打不开 / 无法保存某个文件 | SAF 授权失效，重新用「打开」选择该文件一次 |
| 手机上界面显示不全 | 确认已安装最新 APK（旧包未含最新前端代码） |
| 想改应用名 / 包名 / 图标 | 见下方「自定义配置」 |

---

## 8. 自定义配置

| 配置项 | 文件 | 说明 |
| --- | --- | --- |
| 应用名 / 包名 | `capacitor.config.ts` | `appId`（包名，如 `com.emd.app`）、`appName`（显示名） |
| 版本号 | `android/app/build.gradle` | `versionCode`（整数，安装更新需递增）、`versionName`（如 `1.0`） |
| 应用图标 | `android/app/src/main/res/` 下各 `mipmap-*` 目录 | 替换 `ic_launcher*.png` |
| 首次启动白屏配色 | `android/app/src/main/res/values/styles.xml` | 启动页背景色 |

> 修改 `capacitor.config.ts` 中的 `appId` / `appName` 后，需重新执行 `npx cap sync android`，且**包名变更后需先卸载旧版**再安装。

## 9. 本地浏览器预览（可选）

不打包手机时，可在浏览器中直接开发预览：

```powershell
npm run dev
```

访问 http://localhost:5173/ 。浏览器环境下打开/保存文件走 File System Access API 或下载降级，体验与真机略有差异（真机使用 SAF 原生选择器）。
